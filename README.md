# FnStyle

面向飞牛 fnOS 的独立应用，把**界面美化**、**主题素材**与**主机监控**装进同一个 fpk：

- **个性化设置** —— 改写登录页与桌面的标题、LOGO、壁纸、任务栏样式，一键应用到系统，卸载时自动还原原生样式。
- **主题库** —— 内置主题素材库，一键把整套主题资源应用到登录页与桌面。
- **系统监控** —— 处理器 / 内存 / 存储 / 温度 / 网络 / 功耗的实时看板，带用电量统计、阈值门限与告警推送。

以独立 fpk 应用分发，安装后即可用，不依赖任何其他软件。

## 功能

### 一、个性化设置

5 个分组共 14 个可配置项，配置存于应用数据目录，改完点「应用到系统」即生效。

| 分组 | 可配置项 | 默认值 |
|---|---|---|
| **网站信息** | 网站标题（浏览器标签页标题，登录页与桌面一致） | `飞牛 fnOS` |
| | 网站描述（分享到社交平台时显示） | `飞牛 fnOS 私有云存储系统` |
| **登录框** | 登录框透明度（0 = 全透明，30 = 最不透明） | `30` |
| | 登录框名字（是否在登录框上显示设备名字） | 隐藏 |
| | 登录框水平位置（相对屏幕宽度偏移，0 = 居中） | `60%` |
| | 登录框垂直位置（相对屏幕高度偏移，0 = 居中） | `0%` |
| **桌面与窗口** | 任务栏沉底横置（贴底并横向排列） | 开启 |
| | 窗口毛玻璃效果（作用于登录框卡片，-1 = 系统默认，0 = 关闭） | `8` |
| **图片与壁纸** | 飞牛登录背景（支持 MP4 视频） | 出厂图 |
| | 飞牛登录 LOGO | 出厂图 |
| | 飞牛设备 LOGO | 出厂图 |
| | 飞牛网页 favicon | 出厂图 |
| | 桌面默认壁纸（支持 MP4 视频） | 出厂图 |
| **卸载与还原** | 卸载后自动还原系统默认样式 | 开启 |

- 5 个媒体字段均支持**上传、预览、点「默认」恢复出厂图**，出厂素材随安装包一起播种。
- 登录背景与桌面壁纸支持 **MP4 视频壁纸**（后端按文件魔数校验后单独存放）。

### 二、主题库

- **打开即有内容**：安装时播种 **31 个主题**，首屏直接可见，无需手动点「重载选库」；后台静默增量更新，失败自动重试、不清空已有主题。
- **5 个预置库源**，可勾选启用、重载，也可自行**添加 / 编辑 / 删除**库源（名称、描述、提供者、地址均可配）。
- 每个库源都留有**离线快照**（合计 112 条主题），外链超时或返回错误页时自动回退快照，不会出现空列表。
- 主题预览弹窗提供 **4 个视图**：登录页效果 / 桌面壁纸 / 登录 LOGO / 设备 LOGO；底部可「应用到系统」，把该主题的 **5 类资源**（登录 LOGO、登录背景、设备 LOGO、桌面壁纸、网页 favicon）一次性写入。

### 三、系统监控

单个「📊 系统监控」标签页，从上到下四个区块，页面打开即开始采集。

**概览区** —— 6 张卡片：**处理器**、**内存**、**存储**、**网络**、**温度**、**功耗**。每张卡显示实时值与趋势线，点击可展开该指标的详情抽屉。

**存储**
- 每个存储池的容量、已用、使用率进度条。
- 逐盘 **S.M.A.R.T. 健康**（重映射扇区、待处理扇区、不可纠正错误、UDMA CRC 错误等计数）、硬盘温度、通电状态、电源状态。
- **SMART 全盘巡检**：后台每 6 小时自动巡检一轮并入库，也可点「🔍 立即巡检」手动触发；「巡检历史」可查往期记录，按**硬盘序列号**索引（设备名会随重启轮换，序列号才能认出同一块盘）。
- 缺陷数量异常增长时判定硬盘故障。

**处理器 / 内存 / 显卡**
- 处理器：使用率、型号、核心数 / 线程数、频率、负载。
- 内存：使用率、总量、可用量、频率，**内存插槽信息**（数量、型号、容量）。
- 显卡：占用率与显存占用，支持 **Intel 核显**（i915 / xe 引擎计数，PMU 不可用时回退 RC6 驻留时间估算）、**NVIDIA**（nvidia-smi）、**AMD**（amdgpu / 驱动 gpu_busy_percent）三类。

**温度和散热**
- 系统温度（CPU / 主板 / 风扇位传感器）与硬盘温度，多源采集与风扇转速。

**能耗**
- 实时功率曲线、今日用电量、本月用电与本月预计、全年估算。
- **电价可配**：单一单价（元/kWh），出厂默认 `0.5224`，换算今日 / 本月 / 全年金额。
- 「用电计算」抽屉给出今日、本月、本月预计、全年估算四项。

**阈值门限与告警推送**

| 指标 | 留意 | 严重 |
|---|---|---|
| 处理器使用率 | 85% | 95% |
| 内存使用率 | 85% | 95% |
| 存储容量 | 85% | 95% |
| 系统温度（CPU / 主板 / 风扇位） | 60℃ | 75℃ |
| 硬盘温度 | 50℃ | 58℃ |

> 上表是**参与告警推送**的 6 类指标。另有「通用进度条着色」（70% / 90%）与「巡检缺陷增长判故障」（≥ 10 个）两个阈值只影响界面显示与硬盘判定，不单独推送。

- 全部 **13 个阈值**均可按需修改，校验规则：**留意值必须小于严重值**，单项越界拒绝保存，配置损坏自动回落默认值。
- 告警引擎在**服务端独立线程**运行（15 秒一个判定周期），**浏览器关掉也继续推送**。
- 判定口径与看板一致：容量与温度**取最大值不取平均**（避免单块盘快满被平均值稀释），缺数据一律跳过，不把「没采到」当成「正常」。
- **逐盘逐项**判定，不合并成一条；第二块盘的问题不会被当成「同级别重复」而丢掉。
- 去抖：边沿触发（只在从不超到超的那一刻发）、同指标同级别静默期（默认 300 秒）内不重复、等级从留意升到严重时立即发。
- **通知通道**：
  - **Webhook** —— POST 到用户填写的地址，飞书 / 钉钉 / 企业微信等机器人格式通用，支持加签密钥；一次推送把本次所有告警**合并为一条消息**。
  - **系统通知中心** —— 代码已实现探测与投递，但 fnOS 当前未对第三方应用开放该接口，探测不可用时会**如实返回失败**并降级为「仅记录」，不假装成功。
- 「**测试推送**」可验证通道配置是否正确；配置抽屉底部实时回显最近一次判定时间、超限项数与逐通道推送结果。
- 告警配置默认**关闭推送**，需在「⚙️ 配置管理」抽屉中显式开启。

**数据留存与刷新节奏**

- 历史数据存于应用数据目录下的 SQLite：原始采样点保留 **7 天**，按自然日汇总的日用电等指标保留 **400 天**。
- 归档按完整自然日结算，水位线永远不超过今天 00:00；清理时**先归档再删**，保证凡是被删掉的数据都已进汇总表。
- 刷新节奏：前端拉取 **3 秒**；处理器采样窗口 **5 秒**（与系统自身「运行状态」卡片对齐）；主采集循环 **3 秒**；告警判定 **15 秒**；历史入库 **60 秒**；SMART 全盘巡检 **6 小时**。
- 各指标由 5 个后台线程独立采集（主采集 / 处理器采样 / 硬盘巡检 / 历史写入 / 告警），HTTP 请求只读缓存，不阻塞页面。

### 安装步骤

**方式 A · 应用中心**：fnOS「应用中心」→「手动安装」→ 选择 fpk 文件。

**方式 B · 命令行**（宿主上以 root 执行）：

```bash
trim-cli app install-fpk fnstyle_1.1.90_all.fpk --dry-run --yes
trim-cli app install-fpk fnstyle_1.1.90_all.fpk --yes
```

> ⚠️ **不支持覆盖安装**，升级需先卸载再装。卸载不会删除数据目录里的配置、主题与上传图片。
> 装完请打开应用**再点一次「应用到系统」**，并强制刷新浏览器（Cmd/Ctrl + Shift + R）——运行时脚本由这一步部署到系统 `www/`。

环境要求：飞牛 fnOS 0.9.0 及以上，x86 / ARM 均可，系统自带 `python3`。

## 卸载与还原

软件内置「卸载后自动还原系统默认样式」开关（默认开启），无需另装任何还原工具。卸载采用**两段式**，避免触发 fnOS nginx 停启重建、切断应用中心的卸载请求：

1. **同步阶段**：只中和还原源 `www.zip / tow / raw`，完全不写 `/usr/trim/www/`，卸载请求正常返回。
2. **后台阶段**：独立进程延迟 12 秒后再处理 `www/`、两轮复查并逐项自检，结果写入 `restore_status.json`。

四处写入源（`www.zip`、`tow/`、`raw/`、`www/`）里的注入脚本会被替换为无操作占位、配置写成中性值（`{"__fnstyleDisabled": true}`），因此即使系统重建 `www/` 也不会把旧样式带回来；运行时脚本读到中性配置会自行停止套用并自动强刷一次。`raw/` 一路只清理本应用专属条目，不触碰其原生基线资源。卸载与还原日志位于 `/usr/trim/share/.restore/fnstyle-guard/`。

## 自动更新提醒

FnStyle 内置**「有更新自动提醒」**能力，无需接入任何第三方应用商店，纯靠公开 GitHub 仓库即可工作。

**工作原理**（避开 fnOS 浏览器跨域限制）：

1. 打开软件时，前端请求本地后端 `GET /api/version`（自动检查默认开启，无需任何设置）。
2. 后端（NAS 侧）**并行探测 11 个远程版本清单源**做语义化版本比较（一次并发完成，总耗时≈单源超时，按内地可达性优先取首个成功者）：
   - `fastly.jsdelivr.net` / `gcore.jsdelivr.net` / `testingcf.jsdelivr.net` / `cdn.jsdelivr.net` 的 `gh/xandy0209/Fnstyle@main/version.json`；
   - `ghfast.top` / `gh-proxy.com` / `ghproxy.net` / `github.moeyy.xyz` / `ghproxy.cc` 反代 GitHub raw；
   - GitHub raw 直连；GitHub Releases API 兜底。
   - 响应中的 `via` 字段记录实际命中的源；`attempts` 数组记录**每个源的 curl 退出码与 HTTP 状态码**。
   - 全部不可达时后端仍返回 200 响应并带 `checkError:true`，前端显示「无法连接更新源（可达 x/n）」，悬停状态文字或查看浏览器控制台可得逐源明细；NAS 上每次探测同时写入 `/tmp/fnstyle_version_check.log`。
   - 清单地址可由环境变量 `FNSTYLE_VERSION_URL` 覆盖为单一自托管地址（便于内网/私有部署）。
3. 发现更高版本时，本地后端直接完成安装编排（**零人工介入**）：
   - 后端 `POST /api/update/start` 在 NAS 侧**后台静默**下载 fpk（jsDelivr 多镜像互换 + gh 代理兜底）→ 校验 SHA256 → 调用 `trim-cli app install-fpk` 安装 → 应用中心自动重启服务；
   - 安装脚本用 `start_new_session` 脱离会话运行，应用中心重启本服务也不影响安装继续；若 `install-fpk` 拒绝已安装的同名包，则回退到 `uninstall` + `install`，并在该路径下备份/恢复 share 目录的 `fnstyle.json`，避免配置丢失。
   - 前端顶栏实时显示进度：**下载中 X% → 正在安装 → 即将重启**；顶部横幅提供「立即更新」按钮（手动触发同一流程）。

网络失败、清单不可达或已是最新版时静默降级（`updateAvailable:false`），不报错、不阻塞界面。

**说明**：设置页不再有「更新」卡片——自动检查更新与自动安装更新均**默认开启**（无开关界面），检查/更新入口在顶栏右侧版本号旁。「忽略此版本」写入浏览器 `localStorage`，不写入 `fnstyle.json`。

要发布一个新版本，只需：在仓库根目录 `version.json` 更新 `version` / `downloadUrl` / `sha256` / `changelog`，并将新 fpk 提交到仓库 `dist/` 目录、打对应 tag、上传到 GitHub Release 即可，客户端会自动感知并在后台完成更新。

## 从源码构建

```bash
git clone https://github.com/xandy0209/Fnstyle.git
cd Fnstyle
bash build.sh              # 产出 ./fnstyle_1.1.90_all.fpk（仓库根目录）
```

`build.sh` 输出到仓库根目录，发布前需自行 `cp` 到 `dist/`。脚本会重算 `manifest` 的 `checksum`（即 `app.tgz` 的 MD5）。

本地预览：`python3 preview.py`（默认端口 8765，被占用时自动顺延）。

## 验证

## 说明

本项目通过改写 fnOS 系统 Web 资源实现个性化，属于系统级定制。首次使用建议先备份 `/usr/trim/share/.restore/` 下的原生副本；本软件安装时也会在系统级 guard 目录留一份基线。
